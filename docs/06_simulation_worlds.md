# 6. Simulation worlds (`rover4ws_gazebo/worlds`)

Select with `ros2 launch rover4ws_navigation prototype.launch.py world:=<name>`.
Both worlds use a grass ground plane (tiled texture → features for visual odometry and depth),
a light-blue sky, no shadows, and spherical coordinates lat 38.0 / lon −78.5 (placeholder — set your
test site before using `/gps/fix`).

## 6.1 test_yard (default)

Robot spawns at (0, 0) facing +x. Default goal (12, 0).

| Object | Position (world) | Size | Purpose |
|---|---|---|---|

| crate_b / crate_c | (5.5, +1.0) / (5.5, −1.6) | 0.5 × 1.4 × 0.4 each | 1.2 m gap between them |

Open space for odometry loops: spawn at (−8, −10).

## 6.2 stone_yard

Generated by `make_stone_yard.py` (seed 3) → `stone_yard.world` + `stone_yard.json`.
**Edit the script, not the .world file**, then run `python3 make_stone_yard.py` and `colcon build`.

Robot spawns at (0, 0) facing +x. Suggested goals: (14, 0) and back to (0.5, 0).

| Object | Where | Size | Expected behaviour |
|---|---|---|---|
| 40 pebbles (gravel patch) | x 1.5–4.5, y ±1.3 | 1.5–3.5 cm high, ≥ 0.18 m apart | **drive over** (below the 6 cm step limit) |
| rock_1 … rock_7 | (6.0, 0.2), (6.4, −1.9), (9.0, 1.3), (9.6, −1.0), (12.3, 0.3), (4.2, 2.9), (3.6, −3.0) | 0.35–0.65 m high, 1–3 half-buried spheres | **avoid** |
| walker (actor, `walk.dae`) | x = 7.5, y −3.5 ↔ +3.5 | 0.6 m/s, ~25 s loop | slow / stop, continue |
| cart (actor, orange box) | x = 11, y +3 ↔ −3 | 0.4 m/s, ~34 s loop | slow / stop, continue |
| wall_far (bricks), fence_left, fence_right | x = 17; y = ±5.5 | | boundary + VO features |

**Actor caveats**
- Actors are animated: the camera and depth camera see them, but they have **no collision** and
  follow their script blindly — they never avoid the robot. When the robot stops in their lane they
  pass straight through it. `nav_test.py` reports such events as `CONTACT` (robot stopped) vs
  `COLLISION` (robot moving > 0.2 m/s).
- Actor positions are deterministic functions of sim time (script loops from t = 0), which is how
  `nav_test.py` computes clearance to them from `stone_yard.json`.
- For people that *react* to the robot, Gazebo's `libActorPlugin.so` could be used (then positions
  must be queried from Gazebo instead of computed).

**Generator structure** (`make_stone_yard.py`): edit `ROCKS` (name, x, y, list of
`(dx, dy, sphere radius, height above ground)`), `WALKER` / `CART` waypoints `(t, x, y, yaw)`
(yaw 0 = walking along +x), the gravel rectangle and count in `main()`, and boundary `box(...)` calls.
The JSON written alongside lists rock footprint circles, boundary boxes and mover trajectories.

## 6.3 Adding a new world

1. Put `<name>.world` in `rover4ws_gazebo/worlds/` (installed by `install(DIRECTORY … worlds)`).
2. Keep a textured ground (featureless ground breaks VO) and a `spherical_coordinates` block.
3. `colcon build`, then `world:=<name>`.
4. For automatic clearance scoring, add a `<name>.json` in the stone_yard format
   (`static` circles, `boxes`, `moving`) and run `nav_test.py --world <name>`.

## 6.4 Simulation performance notes

- Rendering runs on the RTX 4060 via WSLg/D3D12 (`glxinfo -B` → "D3D12 (NVIDIA …)").
- RGB camera ≈ 23 Hz with the full stack; real-time factor 1.0.
- The perfect depth camera costs a lot of FPS — only enable it when needed (`gt_depth:=true`).
- Gazebo GUI + RViz + Depth Anything all share the GPU; if the real-time factor drops, run with
  `gui:=false`.
